## 一條新辨認的關聯怎麼寫進編年史

維護者確立了收錄原則。兩篇早已發表的研究即使今天才被歸入同一主題，這段歷史也應保留。文章在時間軸依原發表日期排列；分支在兩個修訂版本之間出現。即使一週只能發三條提醒，第四條關聯仍應可從版本與證據表讀回。搜尋條件、回傳上限和日期精度也應隨紀錄保留，讀者才能知道史書涵蓋了什麼。

離線回歸從六筆復健研究開始，只替原有兩筆加上 `Home monitoring` 關鍵詞。經 MCP 重建後，摘要顯示該分支兩筆證據已在第一版，本次新增零筆；版本比較保留了兩個證據識別碼與 2005、2006 兩個原發表年。另一情境是在後版才找到一篇多年前出版的研究，版本比較將它列為本次新觀察，仍保留其出版年。若實際只有兩版資料，agent 應使用「本次辨認的關聯」；只有原始欄位的變更支持補標原因時，才能進一步歸因。[MCP 端到端案例](../../tests/test_chronicle.py) · [版本比較案例](../../tests/test_chronicle_revision_integrity.py)

## 公開來源與館藏如何共同補證

| 研究者遇到的情況 | agent 可執行的動作 | 適合留下的證據 |
| --- | --- | --- |
| 公開書目只有摘要，問題卻涉及具體方法 | 保留候選，再對 Europe PMC 已索引的方法章節補搜，以識別碼取得正文 | 分開記錄章節索引命中、已讀段落或表格，以及仍缺的內容 |
| 團隊可能已持有早期文章 | 由已連接 Zotero Keeper 的 agent 搜尋獲授權的館藏及附件，以確切 PMID／DOI 對齊，核對指定附件的正文 | 保留館藏來源、版本與定位。索引範圍或文章身分不明時，保留待查 |
| PubMed 回報錯誤或這次完全沒有文章 | 依工具回應讀取已保存的 Chronicle，引用其版本與日期；可在另一來源補查候選 | 各自記錄上游故障、空結果和成功讀回的舊版；顯式 PMID 建版仍須向 PubMed 取資料 |
| 只有 DOI 或 Zotero item key | 保留於版本旁的候選清單，待識別碼核實後再收錄 | 記下未進入該版的原因與來源，避免遺漏無 PMID 的歷史工作 |

Evidence 輸出的分母是該版不重複的證據 ID，分子是具有已存全文 artifact 連結的 ID。一般 PubMed 建版只帶入書目；另行抓到全文，也不會回寫舊版。因此分子為零時，仍可依逐篇輸出的識別碼去找全文。取得連結後須實際讀到段落才能核實一項陳述。Zotero 的 Everything 搜尋涵蓋書目、筆記和已索引 PDF，命中後需要核對位置。公開分享全文也要看個別授權。[Europe PMC 章節索引](https://blog.europepmc.org/2025/05/making-sense-of-europe-pmc-answers-to-your-biggest-faqs.html) · [Zotero 搜尋範圍](https://www.zotero.org/support/searching) · [PMC 全文使用條件](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/)

**一篇實際核讀的反例。** 用官方 REST 介面搜尋 `rehabilitation AND METHODS:"gait speed"`，要求一筆，當次來源回報 6,245 筆，回傳 PMID `43002336`、PMCID `PMC13748176`。公開全文顯示這是一篇回顧，Methods 第 Sec2 節把步速列在文獻搜尋詞中。這足以支持「該篇的方法段用到此詞」，若要寫「該研究量測了參與者步速」則缺乏支持。總筆數會隨索引更新，本例只驗證一次章節命中與段落判讀。SDK 另一次執行碰到 25 秒的來源時間上限，須保留其未知總數。這次未查閱私人館藏。[公開查詢](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=rehabilitation%20AND%20METHODS%3A%22gait%20speed%22&pageSize=1&resultType=lite&format=json) · [原文 Methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC13748176/#Sec2)

## 下一輪用什麼證據決定要不要擴充

選一個有既有歷史回顧的主題，請兩位評閱者先凍結一份已知文獻與歷史關聯清單，再依序開啟公開書目、公開章節索引、獲授權館藏。逐層記錄新增找回幾篇、補上哪些年份、多少個預設問題能定位到原文、需要多少人工核對時間。另列索引外文獻、查詢失敗和完全未檢出的參照項目。這能檢驗的是特定主題的增益與成本。

若漏失集中在已核對卻沒有 PMID 的館藏文獻，就有理由加入「按部署或使用者匯入選定書目」的入口，讓公開版本可引用公開書目，受限的附件定位保留在原館藏。若主要缺口是命中正文卻無法找到支持段落，則先改善段落定位與覆核。這兩種結果會導向不同的工程投資與論文主張。

## 本機驗證紀錄

- 四份 Chronicle 測試檔有 198 個案例通過；定向回歸排除一個需要 Windows symlink 權限的案例。變更的八份 Python 檔案通過 Ruff、格式與 mypy 檢查，非同步測試檢查通過。三組更新的技能與 plugin 副本逐位元組相同。
- Windows 全套 pytest 為 4,940 通過、71 跳過、5 失敗、2 個測試生命週期錯誤。5 個失敗分別涉及 plugin 產生檔換行、用 cp950 讀 UTF-8 設定、建立 symlink 的系統權限，以及兩個出版材料原始位元組雜湊檢查。兩個錯誤源自同一案例的測試名稱超過 Windows 環境變數長度。全域 mypy 另報三個 POSIX `fcntl` 屬性錯誤。上述基線項目留待跨平台維運輪處理。
