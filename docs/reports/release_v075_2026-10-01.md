## Scope

The user authorized final review, fixes, documentation/website/memory updates,
segmented commits, push and publication of v0.7.5. The release branch inherits

the shared boundary for all 41 tools. Successful response bodies remain compatible;
tool metadata advances to contract version 4 and adds structured input errors.

## Follow-up findings and fixes

| Reproduced problem | Correction | Regression evidence |
| --- | --- | --- |
| A malformed PMID JSON batch became a generic identifier error inside a Pydantic validator | Retain the known transport exception's static code/message; never serialize arbitrary validation context | Syntax, duplicate-key, non-finite constant and oversized-string cases fail before execution, then succeed after one repair |
| `int \| float` advertised decimal strings but the integer branch prevented decimal conversion | Try each eligible scalar representation while preserving strict final types/bounds | Published schema and protocol both accept `" 1.5 "` and `" 2 "` |
| An enum branch could rewrite text accepted by a string union branch, or advertise a repair that bypassed a bounded string schema | Preserve literal text and suppress enum repair alternatives for such unions | Exact text preserved; over-length text rejected consistently by schema and server |

Input-contract regressions now run in the independent CI smoke gate as well as
the full local gate. All-tool acceptance verifies native and corrected inputs
against Draft 2020-12 schemas, 41 pre-execution rejections with one repaired retry
per tool, and 60 successful semantic calls per transport pass. Source stdio,
Streamable HTTP and a fresh wheel are exercised with external networking blocked.
