# v0.7.6 background fulltext integration review — 2026-10-01

Status: prepared for publication; release verification is pending.

## Scope and decision

The user requested a focused refactor/quality review alongside background fulltext,
then merging the completed work to master and publishing a patch. PR #22 contains
the original bounded prefetch, these integration fixes, documentation and v0.7.6
metadata. Existing unrelated pull requests are outside this feature's scope.
This checkout has no Git superproject or downstream extension release to update.

Keep opt-in XML prefetch and ordinary demand caching. Keep one explicit fulltext
read: it selects evidence and controls response size without injecting unread
papers into search responses. No additional tools, polling service, durable queue,
parsed-document cache, default-on downloads or live-provider benchmark is needed.
See the [assessment](../design/FULLTEXT_PREFETCH.md) for bounds and tradeoffs.

## Findings and corrections

| Reproduced problem | Correction | Regression evidence |
| --- | --- | --- |
| A requested article still queued behind speculative work | Track whether source I/O has started; promote only queued work into foreground retrieval | Reads start without releasing unrelated background work; concurrent readers and cancellation retain one download |
| Missing body titles silently became abstract text | Extract application `SectionSelection`; report available/unmatched titles separately from source coverage | No abstract substitution or PDF/institutional fan-out; one corrected read shares XML in JSON, TOON and Markdown |
| Abstract-only XML was treated as fulltext success | Require body text before considering structured retrieval satisfied | Normal PDF fallback still obtains real text |
| Agent had to construct a read and snapshots always advertised three candidates | Return native `read_request` arguments and the actual operator limit | Published schema plus real stdio/HTTP/fresh-wheel tool execution |
| Repeated request construction for PMID/PMCID/DOI | Construct one normalized application request from the domain identifier | Existing identifier and fulltext contracts retained |

The new selection diagnostic describes structured XML, not section support in
unstructured fallback text. `coverage_status` still describes source completion;
`fulltext_available` describes whether content was returned. A `not_found`
selection does not mean that the article is unavailable. Requested explicit
extended-source/link/figure work retains its existing policy.

The final PR review also found an unhashable `fulltext` value bypassing the
application string-type loop. It now raises a field-level `ValueError` before
execution; list, dict, boolean and integer regressions cover that boundary.
The fulltext skill now actually enables prefetch in its example and reads the
returned PMCID. Both user guides use the current discriminated `source` object.
